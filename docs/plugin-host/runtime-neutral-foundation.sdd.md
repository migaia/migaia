## 0. 状态与闭合规则

状态只按 `pending → red → implemented → verified` 流转。每个非 deferred 条款必须映射至少一个 `PH-T`，每个 `PH-T` 必须反向映射条款。完成声明必须记录命令、测试数量、日期及 SHA 或 dirty-worktree 基线。当前 PH-R01～PH-R15 为既有实现基线；PH-R16～PH-R39、PH-T16a～PH-T39d 已实现但尚未完成独立对抗复核；文档整体仍不得标记 verified。

## 1. 目标与范围

PluginHost 是跨 Node、Bun、Deno、Browser、Worker、Electron 与小程序复用的插件基础层。公开边界包括 `use/useSync/update/unUse/dispose`、shared、extension、三种 pipeline 与 Readonly config facade。

目标：一个 lifecycle owner、一个 mutation queue、一个 disposer stack、一个 config ownership 模型；保持调用顺序、Promise identity、error identity、receiver 与公开 export。非目标：safeUse、static global plugin API、Store 适配、宿主专属 timer/进程/DOM 行为。

## 2. 现状与问题

当前分层已收敛到 `host-runtime/config/core/disposal/typing`，Readonly config 已使用 WeakMap 懒代理 + Copy-on-Write。AF-63 曾确认资源释放入口存在 TOCTOU；PH-R16 已把 disposer getter、函数和 receiver 固定在 admission snapshot，并由 PH-T16a～PH-T16d 覆盖。该项在下一轮 Sol 复核前保持 `implemented-unverified`。

历史测试数量仅是当时证据，不是当前完成证明；旧文档的“123 tests passed”已删除，最终数量以 §8 重新执行结果为准。

AF-76/AF-83 的第二/三轮 Luna 复核补充：plugin hook 与 Symbol disposer 需要和 resource disposer 使用同一 admission snapshot/receiver 规则；Date/RegExp proxy/clone 与 Map/Set key lookup 需要保持 alias/key identity。两项已有实现与回归证据，但仍是 `implemented-unverified`。本轮补充 cycle-aware config COW：更新无关或替换键时必须重建 owned root、回基 root alias，并在 hook 失败时保持旧 snapshot。Sol 新 findings 继续由 foundation main 分配 AF 编号；本文件只登记对应 PH package cases，不改动 Store 或 review audit 文档。
本轮 Luna HIGH findings：Map/Set reader dispatch 不得以可变的 live prototype identity 将 subclass override 误判为 native reader；clone 与 COW graph discovery 不得调用可覆盖的 `Symbol.iterator`，否则会丢失 entries/aliases/root-reacher edges。修复限定于 `packages/plugin-host`，不引入 foundation/Store 依赖。
Round25 HIGH finding：Date/RegExp/Map/Set subclass 的 readonly facade 不得返回 caller raw prototype；admission clone、readonly prototype facade、prototype cycles/aliases 与 native internal-slot semantics 必须分离，且 branded target 的 `getPrototypeOf` trap 仍须满足 Proxy invariants。修复限定于 `config.ts` 与 plugin-host tests/docs。
Round17 callable finding：config function 值必须进入 owned clone/COW graph。支持可调用普通函数及其 writable prototype、configurable data properties；readonly view 保留调用 receiver、行为与 constructability。class/non-writable prototype、accessor own property、non-configurable custom property 等无法满足 Proxy invariant 的形状在 admission 拒绝，不能泄漏外部 function identity 或 mutable owned property。Round18 补充：non-constructable method 以 callable Proxy 保留动态 receiver；constructable readonly callable 以私有 `new.target` facade 暴露 readonly function properties，但以 ordinary construction prototype 创建实例，避免 readonly proxy 进入实例 prototype 链；ordinary/derived `this` own writes、`instanceof` 与 explicit object-return 均保持，explicit object result 在返回边界重新 owned clone，constructor 不能经 `new.target` 或 inherited config value 修改 owned config。
Round19 callable return finding：readonly callable `apply` 必须在返回边界保护 object-like 结果。sync object/function 结果使用当前 readonly facade cache；不把任意 closure-captured application object 纳入 config COW ownership。thenable 只读一次并以原 receiver assimilation，fulfilled object/function 重新进入 readonly facade，rejection 保持原 identity；sync/async iterator 与 generator 只建立 lazy protocol view，不提前消费，`next/return/throw` 仍以原 iterator receiver 执行，yield/return object value 共享 facade alias，错误 identity 保持。该边界保护调用输出，不承诺阻止 callable body 自身直接修改其 closure 外部对象。
Round20 callable output findings：普通 output facade 不得把 mapped value 放在原始 object-valued non-configurable/non-writable descriptor 后面，必须使用 invariant-safe facade target；该边界覆盖 frozen/sealed/non-extensible/accessor/symbol/array shapes，不改变外部对象。Promise/native thenable 节点在整个 output graph 复用同一 native Promise boundary identity；identity 必须在 fulfillment mapping 前登记，以保留 promise self/back-reference、重复引用、nested await 与 rejection/error identity；then getter 只读一次，then 调用 receiver 保持原对象，getter/call 失败不得制造未观测 rejection。Native Promise 不作为普通 Proxy target。
Round21 Proxy invariant findings：iterator output 不得以 raw iterator 作为 Proxy target，因为 own locked `next`/`return`/`throw`/protocol methods 与 object-valued fields 会禁止 readonly substitution；新 target 复制 own descriptors，保存 raw receiver，按需包装结果，保留 frozen/non-extensible shape、ownKeys 与 descriptor consistency。Callable output 同样使用 callable forwarding target，先登记 public proxy 再 materialize mapped own descriptors，避免 frozen function 的 locked symbol/object properties 触发 invariant TypeError；apply/construct 仍调用原 callable，public `prototype`、receiver、async/generator output 与 aliases 保持。
Round22 iterator accessor finding：`initializeIteratorTarget` 只对 `next`/`return`/`throw`/`Symbol.iterator`/`Symbol.asyncIterator` 使用 raw-receiver method wrapper；ordinary data accessors 必须保留 raw getter receiver、每次访问单读、object result readonly wrapping、throw identity、symbol key、setter rejection、locked descriptor 与 aliases/cycles，不能因误走 method path 变成 `undefined` 或泄漏 raw value。
Round23 prototype/iterator finding：config initial clone 必须为自定义 `Object.create(proto)` 节点拥有 prototype graph；readonly config/output 的 `Object.getPrototypeOf` 只能返回缓存的 readonly prototype facade（`null` 保持 `null`），不得暴露可变 raw prototype 或 raw nested values。prototype cycles、重复 identity、method/constructor/`instanceof` 语义与 Proxy invariants 继续保持。iterator classification 只能沿 own/prototype descriptor chain 判断形状，不得读取或吞掉 `next`、`Symbol.iterator`、`Symbol.asyncIterator` getter；accessor protocol 延迟到首次公开 getter/iteration 读取一次并原样抛错。
Round26 HIGH finding：COW graph discovery 记录 own data/collection edges，却遗漏 custom prototype → root/ancestor edges；无关 patch 后 affected node 因此错误共享旧 prototype，back-reference 留在 previous snapshot。`configObjectChildren` 必须纳入 owned non-intrinsic prototype edges，且仅以 native-brand probe 读取 Map/Set entries，避免把不具 internal slot 的 subclass prototype 当作 collection clone/traversal target。Date/RegExp/Map/Set intrinsic parents 继续作为 native boundaries；readonly prototype facade/cache、Proxy invariants 与 AF-201 behavior 不得改变。修复限定于 `packages/plugin-host` 与本 SDD。
Round27 HIGH finding：callable clone 已复制 own properties 与 callable `.prototype`，却未设置 function object 自身的非 intrinsic `[[Prototype]]`；因此 admission 后 callable 的 custom static/inherited graph 丢失，COW discovery 虽可见 prototype edge 也无法在新 root 中重建。callable clone 必须在同一 `seen` graph map 中 clone 并设置该 `[[Prototype]]`，保留 root/ancestor aliases/cycles 与 structural sharing；intrinsic `Function.prototype`、call/construct/`new.target`、own `.prototype`、bound/arrow/non-constructable rules 与 Proxy invariants 不得改变。修复限定于 `packages/plugin-host` 与本 SDD。
Round28 HIGH finding：`cloneConfigPrototype` 只把 `seen` 中的 object clone 当作可复用 prototype；当 callable parent 先由 child 的 `[[Prototype]]` 路径发现，或已缓存 callable clone 再由另一条路径发现时，callable 会被 plain object 覆盖，造成 property-order-dependent callability、prototype alias 与 COW/root-cycle 丢失。prototype cache 必须接受 object/function owned clone；uncached function prototype 必须走既有 callable clone path，不能替换 graph entry。readonly facade 必须让 child 的 public prototype 与 parent callable alias 保持同一 identity，并保留 call/construct、COW rebase、failed rollback 与 intrinsic boundary 语义。修复限定于 `packages/plugin-host` 与本 SDD。
Round29 HIGH finding：ordinary clone path 在 `cloneOwnedPrototype` 完成后才注册 object shell；当 custom prototype 的 own edge 指回 owning object 时，prototype traversal re-enters the owner and creates a duplicate clone. The ordinary path must register an extensible shell before prototype/property traversal, then install the final null/intrinsic/custom prototype without changing descriptors, branded collection/callable branches, or COW `seen` mapping. Readonly prototype materialization must defer mapped data values until read/descriptor access so an owner→prototype→owner cycle cannot create duplicate readonly facades. 修复限定于 `packages/plugin-host` 与本 SDD。

## 5. 生命周期与错误语义

Host 进入 closing 后拒绝新 mutation；已 admission 的 mutation按 FIFO 完成或显式失败。registration install/update/dispose 使用事务与 LIFO cleanup。`dispose()` 首次调用同步发布唯一 Promise；重复与 reentrant 调用复用 identity。Hook/Symbol disposer admission 完成后只使用捕获的函数和 receiver；Date/RegExp facade 与 Map/Set lookup 不能改写原对象身份。

公开失败携带 `@migaia/plugin-host` source 与稳定 code；原错误经 cause 或 `AggregateError.errors` 可达。rollback 错误不得替换 install primary。pipeline stage/downstream 顺序固定。disposer getter failure 属 admission `INVALID_OPTION`；已 admission disposer 调用失败属于 dispose 领域错误。任何 catch 若不重抛必须 report；reporter 失败不得制造未观测 rejection。Readonly Map/Set custom method 的 receiver 永不为 owned target；serialize probe 的 protocol getter/iterator failure 仍由 serialize boundary 保留原 cause。Callable output facade 对 fulfilled object/function、iterator result value 和 generator return value 只提供 readonly view，不把 closure-captured application object 纳入 COW；普通 output object 使用独立 invariant-safe facade target，不把原始 non-configurable/non-writable object-valued descriptor 暴露给 Proxy trap；thenable getter/then invocation 单读且以原 receiver assimilation，Promise/thenable boundary identity 在 graph cache 中先登记，rejection 保留原 identity 并由 boundary 观察；native Promise 不创建 ordinary Proxy。iterator facade 的 `next/return/throw` 错误直接传播，async rejection 不改写 identity，facade 创建不调用任何 advancing method；ordinary iterator accessor 以 raw iterator 为 getter receiver，每次公开读取只触发一次 getter，object result 进入 readonly cache，getter failure 原样传播，setter 继续拒绝 mutation。
