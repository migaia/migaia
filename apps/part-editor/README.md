# apps/part-editor

part 平台的浏览器编辑器，只在本机运行，不部署。它从目录服务读取项目草稿，编辑蓝图与远端模块的 TS 源码，在嵌入的预览中即时看到效果，再把所有修改作为一个原子变更集保存回草稿。保存不等于发布：发布仍由 `partom pull`、`build`、`publish` 完成。

## 运行

编辑器需要一个运行中的目录服务（见 `apps/part-catalog`），以及在应用仓库里以桥接模式运行的预览：

```bash
partom preview --editor --editor-origin http://127.0.0.1:5174 --port 5175
```

```bash
bun src/main.ts serve --service http://127.0.0.1:5173 --preview http://127.0.0.1:5175/ --port 5174
```

- 只监听 `127.0.0.1`，启动后打印 `{ "url": … }`。目录服务的 `--allow-origin` 需要包含编辑器与预览的源。
- 打开页面后输入目录服务令牌与项目名登录。令牌只发给目录服务与预览页的源。

## 编辑

- **蓝图：** 左侧是节点树，可选中、上移、删除节点。属性面板由 part 描述符生成：有 props schema 的字段按 schema 生成，变体是下拉框，另有 `aria` 分组。
- **问题：** 本地规则与预览回发的问题（包括项目自己的规则插件）同时显示在节点和字段旁边；有修复建议的问题带“修复”按钮。
- **预览：** 每次修改后蓝图立刻发给预览页，页面不重新加载。远端模块按模块名热替换。在预览中按 `Alt+Shift+D` 打开 devtools，可选取节点并查看它的增强阶段。
- **远端模块：** 模块列表中，只有构建结果、没有源码的模块是只读的。可以从模板新建模块。保存后的问题按“文件:行:列”列出，点击问题会选中对应行。保存成功后，新模块导出的 effect 出现在处理函数的下拉框中。

## 保存与冲突

保存会把改动过的蓝图与模块组成一个变更集提交，返回每个产物的结果（`accepted`、`rejected`、`conflict`，或因其他产物失败而未写入的 `skipped`）。只要有一个产物没被接受，整个变更集都不写入。

- 如果别人在你读取草稿之后改了同一蓝图的其他地方，第一次保存返回 `conflict`，编辑器自动合并并提示再次保存。
- 如果别人改了你也改过的同一字段，编辑器列出冲突的节点地址与配置组，由你选择保留本地值或服务端的值，再保存。

## 验证

```bash
bun run fmt && bun run lint && bun run typecheck && bun run typecheck:test && bun run test
```

测试会以子进程启动目录服务、预览与编辑器，并用 Playwright Chromium 驱动页面。`test/integration.test.ts` 是平台阶段 4 的整体验收：它先编译 `partom` 可执行文件，再走完发布、编辑、拉取、下发、拒绝、回滚、离线启动与 devtools。重的测试应在仓库独占窗口中运行。
